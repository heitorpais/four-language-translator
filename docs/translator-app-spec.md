# Spec: Four-Language Translator, built-in knowledge and new features

You are extending an existing web app. Read this whole document before you start. Work on **one phase at a time**. At the end of each phase, stop and report (see "Reporting"). Do not start the next phase until I approve.

---

## 1. Context: what exists now

The app is a single web page (attached: `index.html`). It translates a word between English (en), German (de), French (fr) and Portuguese (pt) and shows a grammar card for each language.

Current behaviour you must keep working:

- Four input slots, one per language, each with a flag. Typing in one fills the other three.
- A main variant can be chosen per language:
  - en: US or UK
  - de: DE, CH or AT
  - fr: FR, CA, BE or CH
  - pt: BR or PT
- Other regions are shown (flag only) where they differ. With CH selected, ß is converted to ss.
- Autocomplete from word lists: en 110,120, pt 104,838, de 89,708, fr 53,567.
- Card contents:
  - headword with article, IPA, part of speech and CEFR level (A1–C2)
  - regional pronunciation, and audio for the word and for each example
  - nouns: gender, plural and plural rule
  - verbs: regular or irregular, principal parts and auxiliary
  - adjectives: agreement and comparison
  - prepositions with case (German always shows the case)
  - synonyms, context sentences, usage notes and the Swiss German dialect form
  - "See more forms": full tables, irregular forms in red
  - "More about this word": definition, collocations, idioms, word family, antonyms, etymology and a typical learner mistake
- 13 words are built in. Every other word is currently generated by Claude at lookup time and saved to the library.
- Settings: regions on/off, Swiss German on/off, device or Claude voice, slow speech, 2–4 context sentences and their difficulty, number of suggestions, Wiktionary links (off by default), clear local data.

**The main change:** stop generating entries at lookup time. Every entry must be pre-built and shipped as data with the app.

## 2. Hard rules

1. **No network requests at runtime** for word data. All lookups read local data files or IndexedDB.
2. **Never invent IPA, gender, plurals or verb forms.** These come from source data or from rule-based generation that is checked against the source data. If a value is unknown, store `null` and show nothing.
3. **Mark the origin of every field.** Each field is either `wiktionary`, `tatoeba`, `generated` (by rules) or `claude` (written by an AI).
4. **Keep the licence notices.** Wiktionary data is CC BY-SA 4.0; Tatoeba sentences are CC BY 2.0 FR. Add a visible "Sources & licences" section to the app and keep `LICENSES.md` in the repo.
5. **Keep all current features working.** If a change breaks one, say so in the report.
6. **The UI language and the labels stay as they are.** The dialect is labelled "Swiss German", not "Zurich German".
7. **No new paid services and no API keys** in the shipped app.

## 4. Data format (one entry)

All languages use the same format. Fields that don't apply are `null`.

```json
{
  "id": "de:gehen:verb",
  "lang": "de",
  "lemma": "gehen",
  "pos": "verb",
  "level": "A1",
  "frequency_rank": 87,
  "ipa": { "default": "ˈɡeːən", "regional": { "CH": null } },
  "noun": null,
  "verb": {
    "regular": false,
    "class": "strong",
    "aux": "sein",
    "aux_regional": {},
    "principal_parts": ["gehen", "ging", "gegangen"],
    "irregular_forms": { "praet.1sg": "ging" }
  },
  "adjective": null,
  "governs": [{ "prep": "zu", "case": "Dat", "example_id": "t:12345" }],
  "senses": [
    {
      "id": "s1",
      "gloss_en": "to walk, to go on foot",
      "register": "neutral",
      "translations": {
        "en": ["en:go:verb", "en:walk:verb"],
        "fr": ["fr:aller:verb"],
        "pt": ["pt:ir:verb"]
      }
    }
  ],
  "regional_variants": [{ "region": "CH", "form": "…", "note": "…" }],
  "swiss_german": { "form": "goo", "origin": "claude", "approximate": true },
  "synonyms": ["de:laufen:verb"],
  "examples": [
    { "id": "t:12345", "text": "…", "translations": { "en": "…", "fr": "…", "pt": "…" }, "origin": "tatoeba" }
  ],
  "more": {
    "definition": "…",
    "collocations": ["…"],
    "idioms": ["…"],
    "word_family": ["…"],
    "antonyms": ["…"],
    "etymology": "…",
    "learner_mistake": "…"
  },
  "origin": {
    "ipa": "wiktionary",
    "verb": "wiktionary",
    "examples": "tatoeba",
    "more.learner_mistake": "claude"
  },
  "verified": false
}
```

The noun block holds `gender`, `plural`, `plural_rule` and `plural_regular` (plus the fields in 4.1). The adjective block holds `agreement` and `comparison`, with `comparison_regular`.

Translations always point to entry **ids**, never to plain strings. That is how the four languages are linked.

### 4.1 Fields added in Phase 1 (approved 10 Nov 2026)

These fields are part of the format. `validate.py` checks them.

| Field | Type | Meaning |
|---|---|---|
| `usage_note` | string or null | Short usage note in English (false friend, register, regional use). Origin `claude`. |
| `synonyms_text` | list of strings | Synonyms that have no entry of their own yet. `synonyms` keeps holding ids only. |
| `ipa.narrow` | true, or absent | The default IPA is a narrow phonetic transcription (`[ˈhu.ɐ]`), to be shown in square brackets. |
| `noun.genitive` | string or null | Genitive singular (German). |
| `noun.plural_alt` | list of strings | Further plural forms Wiktionary lists. |
| `noun.irregular_forms`, `adjective.irregular_forms` | object | Like `verb.irregular_forms`: only the forms the rules in `generate_forms.py` do not produce (Phase 2). |
| `verb.present_3sg` | string or null | German only: 3rd person singular present (`hilft`). With `principal_parts` it is the verb's pattern (Phase 2). |
| `senses[].gloss` | string or null | The definition of the sense in the entry's own language. |
| `senses[].origin` | `wiktionary` or `claude` | Where the sense and its links come from. |
| `senses[].route` | object | For each target language, how the translation was found: `de-edition`, `fr-edition`, `pt-edition`, `en-edition`, `via-en`, `via-en-unchecked`, `library`, `none`. |
| `governs[].pattern`, `governs[].meaning`, `governs[].origin` | strings | Present on patterns carried over from the saved library (origin `claude`). |
| `examples[].hl` | [start, end] or null | Position of the headword's form in `text`, for highlighting. |
| `examples[].translation_ids` | object | Tatoeba ids of the translated sentences. |
| `examples[].credits` | object | Tatoeba user names of the authors (attribution, CC BY 2.0 FR). |

Rules that go with them:

- **Unchecked translations.** A translation whose route is `via-en-unchecked` stays in the data but the app must not show it and must not use it to fill the other language slots.
- **Portuguese.** `ipa.default` is always the Brazilian pronunciation. The pronunciation of Portugal goes in `ipa.regional.PT`. A word for which Wiktionary has no Brazilian transcription has `ipa.default: null`.
- **German auxiliary.** `verb.aux` is the auxiliary used in Germany. Where Switzerland and Austria use another one, it goes in `verb.aux_regional` (`{"CH": "sein", "AT": "sein"}` for stehen, sitzen, liegen, hängen). `"sein/haben"` means both are standard everywhere and depend on the meaning (fahren).
- **Owner's overrides.** Decisions that differ from Wiktionary are listed in `build/owner_overrides.json`.

## 5. Phases

### Phase 1: Pilot with 1,000 German words

**Do:**
1. Download the Wiktionary extracts from kaikki.org for de, en, fr and pt, and the Tatoeba sentence and link files, into `/build/raw`.
2. Choose the 1,000 most frequent German lemmas. Use a frequency list you can name and cite.
3. Import them into the format in section 4, including the linked en, fr and pt entries their translations point to.
4. Attach up to 4 Tatoeba sentences per entry. Prefer sentences that have translations in all four languages.
5. Run `enrich_with_claude.py` only for fields that are still empty and allowed to be `claude` origin: learner mistake, usage notes, CEFR level when missing and the Swiss German form.
6. Write `validate.py`. It must check:
   - every entry matches the format
   - every translation id exists
   - no core entry is missing IPA, gender (nouns), plural (nouns) or aux (verbs) unless the source has none
   - no duplicate ids

**Done when:**
- `validate.py` passes.
- You can show 10 complete sample entries: 4 nouns, 4 verbs and 2 adjectives, including at least 3 irregular words.
- You report total size (raw and gzipped) and the percentage of entries with each field filled.

**Stop and report.**

### Phase 2: Generate word forms from rules

**Do:**
1. Write `generate_forms.py`. From an entry's class and pattern, it builds the full conjugation, declension and adjective forms for each language.
2. Store only the forms that differ from the rule, in `irregular_forms`.
3. Test the generated tables against the full Wiktionary tables for all pilot words.

**Done when:** at least 99% of generated forms match Wiktionary. Every mismatch is listed in the report.

**Stop and report.**

### Phase 3: Connect the app to local data

**Do:**
1. Replace runtime generation in `app.js` with reads from `/data`, cached in IndexedDB.
2. Add `sw.js` so the app works offline after the first visit.
3. The card shows the "See more forms" tables from `generate_forms` logic (ported to JS) plus `irregular_forms`. Irregular forms stay red.
4. Audio uses the device's speech synthesis. The current "Claude voice" option stays only if it works without a network call; otherwise hide it and say so in the report.
5. Add the "Sources & licences" section.

**Done when:**
- With the network turned off in the browser's developer tools, every pilot word opens a complete card.
- All settings from section 1 still work.

**Stop and report.**

### Phase 4: Scale up to the tiers

| Tier | Words per language | Content |
|---|---|---|
| Core | 8,000 most frequent | Full entry |
| Extended | The rest of the cleaned list | Lemma, pos, level, IPA, gender/plural or aux, translations |
| Long tail | Rare words | Lemma, pos, translations |

**Do:**
1. Rebuild the autocomplete lists from Wiktionary lemmas plus inflected forms. Drop:
   - proper names
   - abbreviations, unless they are common words (like "z. B." or "etc.")
   - forms that Wiktionary doesn't confirm
2. Core loads on first visit. Extended and long-tail files load per first letter, when needed.
3. Show the final word counts per language. If German or French is below 100,000, report it; do not pad the list.

**Done when:** core tier loads in under 3 seconds on a normal connection, and `validate.py` passes on everything.

**Stop and report.**

### Phase 5: Features

Do these as separate tasks, in this order. Each one needs my approval before you start it.

1. **Lookup by any form:** "ging" or "went" opens gehen or go and names the form ("Präteritum, 1st/3rd person singular").
2. **Several meanings:** the card shows each sense separately, each with its own translations.
3. **Favourites and own word lists.**
4. **Flashcards with spaced repetition** (SM-2 or FSRS), stored locally.
5. **Quizzes generated from the data:** article, plural, auxiliary, preposition + case.
6. **Phrases and idioms** as their own searchable entries.
7. **Register and frequency labels** on the card.
8. **Gender colours** for articles (setting on/off).
9. **Cognate view and false-friends warnings** across the four languages.
10. **Short grammar pages** linked from terms on the card.
11. **Regional differences browser:** all Helvetisms, Austrian terms, BR vs. PT, UK vs. US, FR vs. CA/BE/CH.
12. **Special-character bar and voice input.**
13. **Record yourself and compare** with the audio.
14. **Word of the day, history and personal level tracker.**
15. **"Report an error" button and "verified" badge.**
16. **Export** to Anki, CSV or PDF, plus share links for single cards.
17. **Dark mode and keyboard shortcuts.**

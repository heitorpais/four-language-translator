# Spec: Four-Language Translator, built-in knowledge and new features

You are extending an existing web app. Read this whole document before you start. Work on **one phase at a time**. At the end of each phase, stop and report (see "Reporting"). Do not start the next phase until I approve.

---

## 1. Context: what exists now

The app is a single web page (attached: `index.html`). It translates a word between English (en), German (de), French (fr) and Portuguese (pt) and shows a grammar card for each language.

Current behaviour you must keep working:

- Four input slots, one per language, each with a flag. Typing in one fills the other three.
- A main variant can be chosen per language:
  - en: US or UK
  - de: DE, CH or AT
  - fr: FR, CA, BE or CH
  - pt: BR or PT
- Other regions are shown (flag only) where they differ. With CH selected, ß is converted to ss.
- Autocomplete from word lists: en 110,120, pt 104,838, de 89,708, fr 53,567.
- Card contents:
  - headword with article, IPA, part of speech and CEFR level (A1–C2)
  - regional pronunciation, and audio for the word and for each example
  - nouns: gender, plural and plural rule
  - verbs: regular or irregular, principal parts and auxiliary
  - adjectives: agreement and comparison
  - prepositions with case (German always shows the case)
  - synonyms, context sentences, usage notes and the Swiss German dialect form
  - "See more forms": full tables, irregular forms in red
  - "More about this word": definition, collocations, idioms, word family, antonyms, etymology and a typical learner mistake
- 13 words are built in. Every other word is currently generated by Claude at lookup time and saved to the library.
- Settings: regions on/off, Swiss German on/off, device or Claude voice, slow speech, 2–4 context sentences and their difficulty, number of suggestions, Wiktionary links (off by default), clear local data.

**The main change:** stop generating entries at lookup time. Every entry must be pre-built and shipped as data with the app.

## 2. Hard rules

1. **No network requests at runtime** for word data. All lookups read local data files or IndexedDB.
2. **Never invent IPA, gender, plurals or verb forms.** These come from source data or from rule-based generation that is checked against the source data. If a value is unknown, store `null` and show nothing.
3. **Mark the origin of every field.** Each field is either `wiktionary`, `tatoeba`, `generated` (by rules) or `claude` (written by an AI).
4. **Keep the licence notices.** Wiktionary data is CC BY-SA 4.0; Tatoeba sentences are CC BY 2.0 FR. Add a visible "Sources & licences" section to the app and keep `LICENSES.md` in the repo.
5. **Keep all current features working.** If a change breaks one, say so in the report.
6. **The UI language and the labels stay as they are.** The dialect is labelled "Swiss German", not "Zurich German".
7. **No new paid services and no API keys** in the shipped app.

## 4. Data format (one entry)

All languages use the same format. Fields that don't apply are `null`.

```json
{
  "id": "de:gehen:verb",
  "lang": "de",
  "lemma": "gehen",
  "pos": "verb",
  "level": "A1",
  "frequency_rank": 87,
  "ipa": { "default": "ˈɡeːən", "regional": { "CH": null } },
  "noun": null,
  "verb": {
    "regular": false,
    "class": "strong",
    "aux": "sein",
    "aux_regional": {},
    "principal_parts": ["gehen", "ging", "gegangen"],
    "irregular_forms": { "praet.1sg": "ging" }
  },
  "adjective": null,
  "governs": [{ "prep": "zu", "case": "Dat", "example_id": "t:12345" }],
  "senses": [
    {
      "id": "s1",
      "gloss_en": "to walk, to go on foot",
      "register": "neutral",
      "translations": {
        "en": ["en:go:verb", "en:walk:verb"],
        "fr": ["fr:aller:verb"],
        "pt": ["pt:ir:verb"]
      }
    }
  ],
  "regional_variants": [{ "region": "CH", "form": "…", "note": "…" }],
  "swiss_german": { "form": "goo", "origin": "claude", "approximate": true },
  "synonyms": ["de:laufen:verb"],
  "examples": [
    { "id": "t:12345", "text": "…", "translations": { "en": "…", "fr": "…", "pt": "…" }, "origin": "tatoeba" }
  ],
  "more": {
    "definition": "…",
    "collocations": ["…"],
    "idioms": ["…"],
    "word_family": ["…"],
    "antonyms": ["…"],
    "etymology": "…",
    "learner_mistake": "…"
  },
  "origin": {
    "ipa": "wiktionary",
    "verb": "wiktionary",
    "examples": "tatoeba",
    "more.learner_mistake": "claude"
  },
  "verified": false
}
```

The noun block holds `gender`, `plural`, `plural_rule` and `plural_regular` (plus the fields in 4.1). The adjective block holds `agreement` and `comparison`, with `comparison_regular`.

Translations always point to entry **ids**, never to plain strings. That is how the four languages are linked.

### 4.1 Fields added in Phase 1 (approved 10 Nov 2026)

These fields are part of the format. `validate.py` checks them.

| Field | Type | Meaning |
|---|---|---|
| `usage_note` | string or null | Short usage note in English (false friend, register, regional use). Origin `claude`. |
| `synonyms_text` | list of strings | Synonyms that have no entry of their own yet. `synonyms` keeps holding ids only. |
| `ipa.narrow` | true, or absent | The default IPA is a narrow phonetic transcription (`[ˈhu.ɐ]`), to be shown in square brackets. |
| `noun.genitive` | string or null | Genitive singular (German). |
| `noun.plural_alt` | list of strings | Further plural forms Wiktionary lists. |
| `noun.irregular_forms`, `adjective.irregular_forms` | object | Like `verb.irregular_forms`: only the forms the rules in `generate_forms.py` do not produce (Phase 2). |
| `verb.present_3sg` | string or null | German only: 3rd person singular present (`hilft`). With `principal_parts` it is the verb's pattern (Phase 2). |
| `senses[].gloss` | string or null | The definition of the sense in the entry's own language. |
| `senses[].origin` | `wiktionary` or `claude` | Where the sense and its links come from. |
| `senses[].route` | object | For each target language, how the translation was found: `de-edition`, `fr-edition`, `pt-edition`, `en-edition`, `via-en`, `via-en-unchecked`, `library`, `none`. |
| `governs[].pattern`, `governs[].meaning`, `governs[].origin` | strings | Present on patterns carried over from the saved library (origin `claude`). |
| `examples[].hl` | [start, end] or null | Position of the headword's form in `text`, for highlighting. |
| `examples[].translation_ids` | object | Tatoeba ids of the translated sentences. |
| `examples[].credits` | object | Tatoeba user names of the authors (attribution, CC BY 2.0 FR). |

Rules that go with them:

- **Unchecked translations.** A translation whose route is `via-en-unchecked` stays in the data but the app must not show it and must not use it to fill the other language slots.
- **Portuguese.** `ipa.default` is always the Brazilian pronunciation. The pronunciation of Portugal goes in `ipa.regional.PT`. A word for which Wiktionary has no Brazilian transcription has `ipa.default: null`.
- **German auxiliary.** `verb.aux` is the auxiliary used in Germany. Where Switzerland and Austria use another one, it goes in `verb.aux_regional` (`{"CH": "sein", "AT": "sein"}` for stehen, sitzen, liegen, hängen). `"sein/haben"` means both are standard everywhere and depend on the meaning (fahren).
- **Owner's overrides.** Decisions that differ from Wiktionary are listed in `build/owner_overrides.json`.

### 4.2 Tiers and data files (Phase 4)

Every entry has a `tier` field: `core`, `ext` (extended) or `tail` (long tail).

- **Core** entries have the full format of section 4. On disk they are split in two files per language, so
  the app can be used before everything has arrived: `core-<lang>.json` holds the entries with
  `examples: []`, `more: null` and `origin: null`, and senses without `route`, `origin`, `gloss` and `reverse`
  (a sense lists in `hidden` the languages whose translations must not be shown). `details-<lang>.json` holds
  `{id: {examples, more, origin, senses: [{route, origin, gloss, reverse}]}}`, the senses in the same order.
  Both load on the first visit; `validate.py` checks each core entry with its details put back.
- **Extended** entries hold only `id, lang, lemma, pos, tier, level, frequency_rank, ipa, senses, origin`,
  plus `noun: {gender, plural}` or `verb: {aux, aux_regional}`. Their senses hold
  `id, gloss_en, translations, route, origin`.
- **Long-tail** entries hold only `id, lang, lemma, pos, tier, senses, origin`. Their senses hold
  `id, translations, route, origin`.
- A field missing from an extended or long-tail entry means `null` (or an empty list).
- Extended and long-tail entries, and all inflected forms, are stored in `ext/<lang>/<prefix>.json` as
  `{"entries": [...], "forms": {"ging": ["de:gehen:verb"], ...}}`. The prefix is the word's first letter,
  folded (lower case, accents removed, ß → ss, anything outside a–z → `_`). A letter with too much data is
  split into two-letter prefixes, and so on. `manifest.json` lists every prefix with its version.
- A sense added because another entry links to this one (gehen → ir gives ir → gehen) carries `"reverse": true`.
- Inside each translation list, the translation whose own Wiktionary entry names the source word comes first,
  then the more frequent one.

### 4.3 Regional words (added 11 Nov 2026)

- `senses[].regional` (optional): `{translation id: markers}` for translations that are regional.
  `["BR"]` = Wiktionary labels every matching sense of that word with these regions only (`celular` → BR);
  `[]` = only in regions the app does not offer (Louisiana, Angola…); `"+CH"` = the usual word for this meaning
  in that region; `"-CH"` = not used for this meaning there (laufen for "run"). Regions: DE CH AT, US GB,
  FR CA BE CH, BR PT.
- `senses[].regional_origin` (optional, details file): `{translation id: "claude"}` for markers that come from
  `build/claude/regional_words.tsv` rather than from Wiktionary.
- `used_in` (optional, any tier): the regions where the word is used, when every sense of it carries a region label.
- A list whose first word belongs to other regions only and that has nothing for region R gets R's word from that
  word's Wiktionary synonyms (or, for English, its other spelling: favourite → favorite).
- The app orders each translation list for the reader's chosen region: a word marked for that region comes first
  when the list also holds a word of another region or the marker is `+`; words of other regions only (or `-R`)
  go last; the rest keep the order above. Chips of regional words show their flag; a card whose word is not usual
  in the chosen region says where it is used.
- When the chosen region has no transcription of its own, the card shows the base region's IPA with its flag and
  "as in Germany" (or France, United States, Brazil).

#### Phase 5 as built (approved and done 11 Nov 2026)

- **Files.** `app/app.js` (lookup, cards, search, audio, address of each word), `app/views.js` (Explore, Practice,
  My words, Settings, welcome box, grammar pages, home-screen tip), `app/learn.js` (false friends, gender rules,
  level estimate, grammar notes; origin `claude`), `app/i18n.js` (interface in German, French, Portuguese; English is
  in the code), `app/manifest.webmanifest` and `app/icons/` (add to home screen).
- **Search.** Results as you type; Enter opens the top suggestion; one box for any language (the language that has
  the word wins; the reader's language order breaks ties); accents optional; ss = ß; ae/oe/ue = ä/ö/ü in German;
  idioms searchable; pasted text cleaned; special-character bar and voice input under each box; every word has an
  address (`#/de/Haus~noun`, sense as `/2`) and the back button works.
- **Cards.** Essentials first (compact mode), the rest under "All details"; one-line summary (der Tisch · die Tische,
  geht · ging · ist gegangen) with changed letters marked; gender colours with shapes; level, case, auxiliary,
  register and frequency badges; false friends, gender tips (shown only where the app's data confirms the rule for at
  least 80 % of the nouns), similar words in the other languages, synonyms, opposites, word family, words like this;
  tappable words in the sentences; grammar pages (ⓘ) linked from terms.
- **Levels.** Stored levels (Claude, German pilot) are kept; all other words get a level estimated from the frequency
  rank (≤600 A1, ≤1,500 A2, ≤3,000 B1, ≤5,500 B2, ≤9,000 C1, else C2), shown with ≈.
- **Register.** `build/regions.py` also fills `senses[].register` for core entries when every matching Wiktionary
  sense carries the same label (colloquial, slang, vulgar, offensive, derogatory, formal, literary, dated, archaic,
  humorous, childish, euphemistic).
- **Personal data** (browser only, `flt:me1`): favourites, known words, notes, own lists, history, practice mistakes,
  flashcard schedule (SM-2); export/import as JSON, CSV, Anki text, print/PDF.
- **Practice.** der/die/das, plural, haben/sein, preposition + case, translation in any direction, fill the gap,
  listen and type, principal parts, matching game across four languages, review of mistakes, flashcards with
  spaced repetition; 10 questions a round, filter by level, saved words or a list.
- **Audio.** Device voices only: play all four, tap the IPA, hold for slow, optional autoplay, voice per language,
  read a table of forms aloud, repeat, words lit up as they are spoken, record yourself and compare.
- **Settings** in three groups (Display, Audio, Data), reset to defaults, welcome box ("I speak / I am learning /
  my level") that orders the four boxes, themes Device/Light/Dark/Midnight, text size, animations (off when the
  device asks for reduced motion), keyboard: `/` search, `1`–`4` languages, `?` help.
- **Not done:** a "verified" badge is shown only for entries marked `verified: true`; no entry is marked yet.
